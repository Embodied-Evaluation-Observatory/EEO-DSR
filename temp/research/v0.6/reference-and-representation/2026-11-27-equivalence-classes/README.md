# “同一内容”的三个等价类

日期：2026-11-27。FNR 的目标类必须先定义；没有目标类，FNR 没有确定的分母。

| 类 | 定义 | 当前状态 | 与 W 的关系 |
|---|---|---|---|
| `exact` | 同一 episode 的同一条记录重复；字段相同、UUID 相同 | 58 组 exact 重复记录（raw metadata）；`n_exact_copies = 58` 组 | 指纹按定义相同；W 不改变判定，exact FNR 是构造性的 0，不是检测器性能 |
| `re-encoded` | 同一轨迹经受控重编码/压缩，内容近似但字节不同 | 150 对 0.5% + 150 对 2%；本日曲线只测这一类 | W 改变 FNR；见 `../2026-11-27-fpr-fnr-curve/` |
| `near-take` | 同一任务、同一场景，不同一次执行；语义近但独立采集 | **未定义、未测量** | 无 W 曲线；不能把 near-take 当成 re-encoded 的替代 |

## FNR 目标类声明

- 本仓库当前发布的 FNR 仅针对 **`re-encoded` 类**；`exact` 类只作字段级重复读数；`near-take` 类没有定义。
- 买方必须按自己的去重需求选类集合；不得把 `re-encoded` 的 FNR 当成 `near-take` 的召回率。
- `0/150` 与 `5/150` 是受控重编码样本上的读数/上界，不是真实独立重复的工作点。

## 与 ICR 的冲突

`near-take` 与 ICR 直接冲突：ICR 要的是同一任务下不同执行带来的多样性；去重检测器若把 near-take 判为重复，就会把 ICR 想要的多样性扣掉。两个模块在同一语料上必须显式声明这个冲突，不能各自给建议。

## 补正例的顺序

先定义目标类，再补正例。当前能免费拿到的是 `exact` 类（58 组）和 `re-encoded` 类（受控副本）；`near-take` 需要独立采集的第二次执行，不能由同一 UUID 的重复记录冒充。
