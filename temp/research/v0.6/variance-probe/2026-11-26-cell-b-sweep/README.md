# cell 轴覆盖率-vs-B

日期：2026-11-26。模拟，不是语料读数，不签发 NEES 记录。

## 设置

- 输入：`2026-11-26-r2/droid_cell.csv.gz`。
- 键：`scene_id`，K=53,714，N=93,994，multi=6,602，p_mean=0.8222971679。
- 每个真 ρ 跑 1,000 次模拟；每次模拟内做 B=25/100/500/2,000 的嵌套前缀重抽。
- 重抽在 6,602 个多例 cell 的子群上固定次数进行（Multinomial），不是含单例的全 K 群 bootstrap；单例本来不进 ICC(1)，但这里的选择数因此是固定的。
- 区间：percentile 2.5/97.5；覆盖率自身区间：Wilson 95%，分母为可估点次数。
- 随机种子：20261128。
- 工具：`tools/icc_beta_sim_cell_fast.py`。B=25/100/500 使用同一 B=2,000 流的前缀，不用独立重跑。
- 这是多例子群上的标定，不外推到含单例的全 K 群 bootstrap。

## 结论

1. B 增大确实把覆盖率抬起来：B=25 → B=2,000，低 ρ 区从约 0.85–0.88 升到 0.92–0.94。这一半是 B 的作用。
2. B 不是全部原因：B=2,000 仍没有到 0.95；ρ=0.90 反而从 B=500 的 0.839 降到 0.838，且在 B=25–2,000 全程最低。偏斜没有随 B 消失。
3. 所以 cell 的问题是“B 不足 + 偏斜下 percentile 区间失效”，不是单纯“B 太小”。把 B 从 25 加到 2,000 能改善，但不能单独修好。
4. 论文主读数继续用 B=2,000 估点可以；但 cell 的 95% 区间不能按名义 0.95 报。要么换区间方法，要么明写实际覆盖率。

## 边界

- 覆盖率是条件于可估点的；零方差/不可估点未计入分母。
- 这是 cell 尺寸分布上的模拟，不是对某个真实 cell 的推断。
- `nees_record: not_issued`。
