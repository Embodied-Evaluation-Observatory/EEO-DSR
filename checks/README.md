# 卡片口径明确性检查

页面顶部固定印 EEO-RN-3。

> 本页是卡片口径明确性检查，不是对数据质量的判定，不是对任何标准的符合性判断，不是核验结论。MISSING/AMBIGUOUS 反映卡片披露格式，不代表数据本身有问题。

本检查测两件事：卡片上的数能不能被第三方按同一口径唯一复算；已声明的标识能不能被唯一追溯。它不出具合格结论，也不得被读成“对标准的初步符合性检查”。

## 两道顺序闸与四态

| 闸 | 问 | 出口 |
|---|---|---|
| 闸一：明确性 | 有分项吗？解析唯一吗？舍入约定声明了吗？ | MISSING（无分项）／AMBIGUOUS（多读法）／进闸二 |
| 闸二：自洽性 | 分项之和与总数相等吗？ | PASS／FAIL |

四态互斥且穷尽：`PASS`、`FAIL`、`MISSING`、`AMBIGUOUS`。只给总数、不给任何分项 → `MISSING`，不判 `PASS`。

明确性与自洽性正交，但不平行：先过闸一，再进闸二。口径明确但不平的卡片在闸二判 `FAIL`；有多读法的卡片在闸一判 `AMBIGUOUS`，不会同时落入两态。

## S1 放宽与不放宽

接受任何**已声明**的分解：按本体、按采集方式、按任务、按场景。BridgeData V2 的 `50,365 + 9,731 = 60,096`、RoboMIND 的本体分解，都是合法平账。没有分项就没有可复算性，此条不放宽。

分项必须是卡片上明示的，不是检查者从别处补的。分项之和与声明总数相等才 `PASS`；不等 `FAIL`；有多读法 `AMBIGUOUS`；没有分项 `MISSING`。

## 精度容差必须绑定舍入约定

“在声明精度内一致”若不绑定约定，容差本身有两读法。RoboMIND 的 `107,877` 截断到千位是 `107k`（平），四舍五入是 `108k`（不平）。约定未声明 → 闸一 `AMBIGUOUS`，同时印出两个结果。

不得用容差把一个未声明舍入口径的差额静默吸收。容差只在舍入约定已声明、且分项与总数同一约定时使用。

## AMBIGUOUS 三条准入

1. 歧义类型须命名：附着、作用域、约定。不属这三类不进。
2. 每个读法须是可跑的解析，产出数字；两读法都入库、可重跑。
3. 有数据能裁决时不许判 `AMBIGUOUS`。

DROID 不再作为 `AMBIGUOUS` 例子。镜像子集 93,994 条中失败 16,703，成功 77,291 > 75,000；“75k＝全部成功”算术上不可能；“75k＝那 95%”与实测 82.23% 相容。已裁决，按裁决结果归类。残余的“项目页 76k trajectories vs 镜像 95,658 episodes”属 D1b 卡片对索引，不是 S1 歧义。

`AMBIGUOUS` 示例改用 RoboMIND 的 `107,877` vs `107k`。

## 输入与输出

输入固定为 `checks/cards-source.csv`，只含 `dataset_id` 与 `url`。一个目录一次检索：

```
checks/cards-source.csv
tools/screen_cards.py
checks/dataset/<YYYY-MM-DD>/
  cards.csv        一行一张卡片，一列一项检查
  README.md        查了什么、什么进了集合、怎么哈希的
  index.html       一行一张卡片，一格一项检查
  pages/           逐卡原始页面字节，供复算 page_sha256
  manifest.json    输入与输出文件的清单
  manifest.sha256  manifest.json 的哈希
```

同一天第二次运行不覆盖，改用 `checks/dataset/<YYYY-MM-DD>-r2/`；再往后 `-r3`。旧目录不原地修改。

## 什么进集合

检索当日公开可访问、无需审批、页面描述一个具身数据集或具身数据项目。范围 10–20 张。需要登录或审批才能读文件的页面，只要卡片本身可读仍可进；初筛只读卡，不把“文件需审批”当成“卡片需审批”。

2026-11-26 的 V0.5 集合共 20 张：12 张 Hugging Face LeRobot 卡片，加上 `robomimic`、`calvin`、`robocasa`、`maniskill` 的 GitHub README，以及 `droid`、`openx`、`bridge-data`、`libero` 的项目页。它是可及范围的普查，不是随机样本；平台取样效应尚未消除。

## 集合级读数

每项可判率 = `(PASS + FAIL) / m`；`AMBIGUOUS` 单列，不计入 PASS/FAIL 分子。它是集合上的分布，不是对单张卡片的评级，不出现总分、评分或排名。

- 某项 100% `MISSING`：判为**不可判**，不得计入通过。
- 可判但没有 `FAIL`（全 PASS）或没有 `PASS`（全 FAIL）：判为**无可区分信号**。
- 同时有 `PASS` 与 `FAIL`：判为**有区分**。
- 全部行状态相同：声明“本集合上无区分信号”。

汇总必须分开 `FAIL` 分布与 `MISSING` 分布，另列 `AMBIGUOUS`。三者不可合并成“至少一项不通过”。

V0.5 的 2026-11-26 结果是旧产品口径下的披露度普查：20 张、0 张至少一项 `FAIL`、20 张至少一项 `MISSING`，S4 可判 12/20。它不适用于本页的四态口径；本页迁移后需重跑，旧结果不原地改写。

## 检查项

| 项 | 测什么 | 不通过意味着 |
|---|---|---|
| S1 | 任何已声明分解之和与声明总数一致 | 卡片自己的算术不平；无分项则 `MISSING`；多读法则 `AMBIGUOUS` |
| S2 | `frames/episode`、`seconds/episode` 与卡片声明换算率一致 | 声明的规模无法与另一张卡片比较；只给字段不算声明换算率 |
| S3 | 版本与日期互不矛盾 | 卡片版本与自身元数据不一致 |
| S4 | 许可存在且可机器识别 | 买方无法确认被授予的用途 |
| S5 | 校验和存在（只查存在，不复算全量字节） | 没有任何字节级承诺 |
| S6 | 场景/工位标识可跨表 join | 标识无法在两张表之间连接 |

每个 `FAIL` 格同时显示声明值与重算值；每个 `AMBIGUOUS` 格显示全部读法及各自算术。行按 `dataset_id` 字母序，不按失败数排。

S2 不因为 `total_episodes`、`total_frames`、`fps` 同时存在就 `PASS`。脚本先算两个被比值并印在证据里，只有卡片另声明 `frames_per_episode` 或 `seconds_per_episode` 且与重算在 1% 内一致时才 `PASS`；声明了但对不上记 `FAIL`；没有声明记 `MISSING`。

## 每张卡片的字段

`dataset_id`、`version`、`source_url`、`retrieval_date`（UTC）、`card_last_modified`、`page_file`、`page_sha256`、`card_sha256`，随后 S1–S6 各自一个四态值加声明值/复算值/读法清单。

## 哈希

`card_sha256` 哈希的是解析后的卡片，不是页面：结构化字段按固定字段顺序、无空格 JSON、UTF-8 序列化，附检索日期，一次哈希。序列化结果同时保存在 `manifest.json` 的逐卡记录里。

`page_sha256` 哈希原始页面字节；原始字节存在 `pages/`，可直接用 `sha256sum` 复算。

`manifest_sha256` 是 `manifest.json` 文件本身的 SHA-256。清单含 `dataset_id`、`version`、`url`、`retrieval_date`、逐卡 `page_sha256` / `card_sha256`，以及 `cards.csv`、`index.html`、`README.md` 三个输出文件的哈希。用 `sha256sum -c manifest.sha256` 复算。

第一版由 `tools/screen_cards.py` 自动解析页面上的结构化字段，没有人工转录；README 逐目录标明这一点。若改为人工转录，必须写成“转录自钉住页面”，并仍钉住 `page_sha256`。

上游页面变了就是新版本、新目录。任何结果都不在原地修改。

## 页面

一行一张卡片，一格一项检查。按 `dataset_id` 字母序或按日期排序，绝不按不通过项数排序。每个不通过的格子同时给声明值与复算值；`AMBIGUOUS` 给全部读法。格子里不放形容词。不出现总分、评分、排名。

页首固定印：

> 本页是卡片口径明确性检查，不是对数据质量的判定，不是对任何标准的符合性判断，不是核验结论。MISSING/AMBIGUOUS 反映卡片披露格式，不代表数据本身有问题。

## 本产物不能说明什么

不能说明卡片是否诚实、语料是否可用、覆盖是否够、切分是否干净、标注是否正确。它只报告披露与算术，不给出自洽性结论；结果不得引用为核验结论，也不得用于它没有覆盖的语料。

Phase 0 的 linter 结果独立发布，不进入 T1/T2 记录；记录里的 DSR-D1 是在记录语境下重新执行的口径检查，不直接引用本目录的输出。
